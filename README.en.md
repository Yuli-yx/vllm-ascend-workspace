# MindIE Agent

Domain context, remote execution tools, and a knowledge/experience/usefulness feedback loop for Ascend development.

The `0.0.1` product entry points are [Codex](https://github.com/mindie-agent/mindie-agent-codex)
and [Claude Code](https://github.com/mindie-agent/mindie-agent-cc), used in your own business
repository on macOS, native Windows or Windows WSL. Existing contribution choice and project
scope apply to verified native tasks without daily activation or closing steps.
Knowledge processing runs locally; remote-dev provides remote execution. Complete public
messages are selected and redacted without a body model. An internal native model produces
required retrieval navigation, never replacement body text. The contribution choice persists
across tasks and updates; missing configuration, explicit disable and operational failure remain distinct.

`0.0.1` is an ordinary Release for internal testing, without a beta suffix or prerelease flag.
The [release record](docs/releases/0.0.1.md) lists exact supported Harness versions, six-environment
evidence and known issues. Interrupting a Codex child may leave its pending tool invocation or
remote command running. This accepted first-release limitation does not add a plugin workaround
or block publication. Benchmark work remains separate; this release makes no quality or cost-benefit claim.

Install through the native marketplace using immutable `v0.0.1`, following the selected adapter's
instructions. More than 24 hours after the last successful update check, the next natural use
asynchronously checks for the highest compatible ordinary Release, prepares it in the background
and activates it when idle. Existing authorization is retained.

This repository contains [architecture](docs/architecture.md), [design principles](docs/design-principles.md)
and [next steps](docs/next-steps.md). Component ownership and current evidence are listed in the [Chinese README](README.md).

The former workspace bootstrap, updater, source management, client wiring and automatically exposed Skills
have been removed. No legacy aliases or installation path are provided. Git history retains prior work.
The [unified implementation status](docs/implementation-status.md) distinguishes development,
integration, native acceptance and public delivery, retaining historical revisions and failed attempts.
Kimi is outside this first-release scope. Business benchmarks and upstream known-issue follow-up
continue separately. Old business Skills and profiling remain deferred.
