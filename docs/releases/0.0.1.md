## 系统性修复与证据边界

本次按现象、直接原因、系统原因、修复及验证五层闭环；用户明确耗时不是
降低质量要求的理由。完整因果、原始失败和中间候选见
[发布问题根因分析](0.0.1-root-cause-review.md)。

| 类别 | 确认的问题与结构性处理 |
| --- | --- |
| 后台服务所有权 | 原 Windows Codex Stop 实际 queued，旧快照漏读 captures；原 consumer 退出原因未记录。独立原生实验复现严格外层 Job 在宿主退出时杀后台服务。core 统一按需系统宿主、认证就绪、消费锁及退役；当前 Windows Codex 两次宿主退出后索引完成 |
| 服务复用权威 | CC 私有快路未核对配置指纹，丢弃 worker 状态并绕过 retired；`c96c319` 删除它，统一使用共享 ensure，健康服务仍直接复用 |
| 业务时间与重复计算 | CC RPC、launcher、setup/update 在不同层截断同一业务；分别修正期限来源及已测重复校验、posting 更新和正文分词。实际 Codex 两版默认 MCP tool timeout 为 300 秒，不能用通用 60 秒文档解释 |
| 业务结果与资源清理 | 先保留结果/用量，再确认完整写入树退出，最后移除 core 自有 scratch。Windows 精确 Job 与 POSIX 活进程/僵尸/查询失败分别处理，清理异常不能抹去已发生调用 |
| 外部操作与记账 | 两端 updater 先记 intent，保留 completed/failed/unknown 与次级错误；未知外部写入先只读对账，不盲目重装、回滚或重做模型 |
| 路径表示与物理身份 | 普通/扩展路径共享身份与既有 cursor；Python 深材料与 Git 根边界分别处理，提前拒绝不支持的 Git layout，不隐式迁移或删除状态 |
| 错误诊断 | CC 原生终态保留安全 subtype；安装校验报告具体 Git 步骤和执行/退出/清理事实。已经丢失的历史原因标为未知，不猜成网络或模型故障 |

## 设计原则 Review

依据产品原则提交 `6a81b410301a1791dcefa1f2b005b84bd853f720`，
2026-10-15 在线读取 blob `62cdd5ae40553df2f0f7f7d022141123792d2944` 一致。

1. 总成本：复用普通 Release 和现有安装器，benchmark 独立；不增加 beta 通道。
2. 封闭问题：版本读取、状态声明和候选检查限定在机械交付问题；实际收益不作机械保证。
3. 理解负担：用户只面对 `0.0.1`；内部安装标识与组件编号不形成新操作流程。
4. 单一边界：适配器负责原生打包，共享组件负责状态；此文档不增加运行时或依赖权威。
5. Skill 信息性：本次未增加强制 Skill 流程，发布文档不要求每个业务任务执行检查。
6. 知识参考性：公开发布、索引和检索不等于正确性或收益认证；限制保留。
7. 按需介入：验证仅在已授权的隔离合成任务范围启用贡献，不扩大到用户真实
   项目；不运行 benchmark 模型调用，不把本地模拟投递视为公开写入授权。
8. 成果复用：复用已有状态边界、安装器、固定组件及测试；仅扩展受影响检查。
