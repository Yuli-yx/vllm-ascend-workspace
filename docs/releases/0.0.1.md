## 设计原则 Review

依据产品原则提交 `6a81b410301a1791dcefa1f2b005b84bd853f720`。

1. 总成本：复用普通 Release 和现有安装器，benchmark 独立；不增加 beta 通道。
2. 封闭问题：版本读取、状态声明和候选检查限定在机械交付问题；实际收益不作机械保证。
3. 理解负担：用户只面对 `0.0.1`；内部安装标识与组件编号不形成新操作流程。
4. 单一边界：适配器负责原生打包，共享组件负责状态；此文档不增加运行时或依赖权威。
5. Skill 信息性：本次未增加强制 Skill 流程，发布文档不要求每个业务任务执行检查。
6. 知识参考性：公开发布、索引和检索不等于正确性或收益认证；限制保留。
7. 按需介入：验证使用隔离环境和合成数据，不启用新贡献范围，不运行 benchmark 模型调用。
8. 成果复用：复用已有状态边界、安装器、固定组件及测试；仅扩展受影响检查。
9. 错误可见：缺失/错误候选版本拒绝打包；不同已发布格式拒绝重置；
   执行结果不确定仍保留。未完成的 Claude Code、Windows 和原生验收明确列出。
