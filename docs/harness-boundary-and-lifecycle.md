# Harness 边界与生命周期

当前合同，2026-10-15。继承[九条设计原则](design-principles.md)，服务于[架构](architecture.md)定义的普通原生任务；实现和真实验收见[统一实施进度](implementation-status.md)。本文替代此前可选摘要摘录、每任务手动激活、默认业务总时限和未发布客户端多代兼容的约定。旧版本证据保留在历史记录，不作为本合同已实现的证明。

## 职责与普通使用

适配器拥有原生任务身份、命名 transcript 的可信来源、公开记录解析及该端模型调用；宿主插件管理器拥有插件安装与版本选择。适配器提供发布 manifest、固定依赖与稳定入口，绑定确定的运行时和共享服务配置。共享知识组件拥有中立的授权/游标/队列、脱敏、必要索引、检索、发布回执和恢复。remote-dev 拥有远端执行和产物；diagnostics 拥有有界本地记录与独立选择的故障上报。协调工具和设备观测工具只在实际需要时介入。

不新增统一 Harness、领域路由器、第二套发布数据库或通用任务平台。用户继续使用业务仓库与原生任务。可选知识读取及远端能力不依赖采集激活；查询、反馈、状态和收尾都不是日常前置步骤。Skill 提供入口信息和适用方法，不规定每个任务的研究路线。

## 身份、选择与范围

贡献 choice、公开仓库、账号和项目范围是现有持久配置；新任务、重启、升级不产生第二次授权。缺配置、范围不符、明确停用及读取损坏分别报告。已有 read-only/later 拒绝意图继续作为停用处理，不能升级为公开贡献。独立故障上报的选择不被贡献配置代替。

授权配置与代码安装身份独立，重载插件不等于重新授权。安装身份检查不包含
可变的用户选择；更新后继续读取原授权及范围，明确停用始终有效。

首次配置只询问确实缺失的信息，复用已有明确选择；不新增“只读”或“稍后”产品档位。后续配置支持增量修改，无需重装、手改 JSON 或改动无关插件。安装成功、选择已保存、任务绑定与实际采集/贡献回执分别报告。

每个原生 task/fork 的材料归属来自可信 host 身份与 transcript 头。不能猜测最新会话、相同 cwd、相似输入或其他任务的时间戳。采集下界来自有效授权、task/fork 创建时间及明确关停窗口；内部建库、绑定或首次 Stop 的时间不是新的授权下界。只读当前明确命名的 transcript，不自动发现历史。显式历史导入复用同一投影、脱敏、索引和包协议。

每次外部写均重新读取这些现有授权。撤销阻止未发送动作；已经确认的 push 与未创建的 PR 分开记录。写入回执丢失必须保留 unknown 及原身份，先只读核对，不能当作未发送重试。重开仅承接其后获准材料，不补扫关闭期间的对话。

## 正文与模型

Codex 保留有序的用户输入、助手公开进展和最终回答；排除工具载荷、隐藏推理、注入指令和原生重复事件。机械投影不做语义缩写或首尾截取。Gitleaks 与固定隐私规则在正文、模型输入和发布之前执行。规则不能判定专有业务含义是否可公开，因此不能替代已有项目授权。

完整脱敏正文保存为不可变有序 Markdown 块，游标与有效元数据一起提交。LangMem 通过适配器的原生小模型，为全部新块生成标题/检索摘要及短导航；它不能改正文。每次只处理有界的新块和短导航，长任务继续推进到全部获准内容，不用任务总量阈值丢弃后半段。索引是公开打包的必要步骤，失败保留正文并报告未完成，不能用摘录冒充索引完成。

Codex 内部模型策略属于适配器，不继承业务任务强度，也不增加用户设置。已返回结果和 usage 先保存再本地应用；本地应用失败复用原结果。已提交但结果未知、已失败的模型输入不自动再次付费。查询、同步、包校验和发布不调用整理模型。Kimi 与 Claude Code 需要独立实现并验收自己的原生 worker。

## 操作寿命与错误

任务授权、一次工具操作、MCP 连接、本地进程树与远端持久 job 有不同寿命。默认无业务总执行时限，只有调用者明确要求的期限才交给执行者。安静或运行很久不证明失败；进程句柄、EOF、SSH 连接健康、所有者退出和明确错误决定是否继续。前台等待窗口返回原操作身份，不重新提交。设备租约的心跳与 fencing 保护资源归属，不能被当作业务最长时长。

取消只作用于本次拥有的进程树；明确设计为独立所有者的后台服务与远端持久 job 不随短启动器退出而误杀。已知成功或失败、未提交、外部结果未知分别表示。日志、账本、清理失败不能覆盖已知业务结果和主错误，必须带上剩余失败阶段、原操作身份与必要定位信息。

Stop 只持久准入并通知既有 owner，协议输出不要求业务模型续跑。当前 Hook 的失败通过宿主支持的安全警告字段送达；stderr 仅作补充，不能假定宿主会展示。后台必要阶段的故障进入有界 Agent 诊断，在下一次自然能力调用中送达；只有日志或后台状态不算送达。包装层无法启动解释器或脚本时也须保留可见失败，说明完成情况未确认且不会重放。没有后续调用时保持未交付事实，不能写成成功。用户答复只需要反映其实际目标的结果和直接限制，不增加 MindIE 运维流程。

摘要操作的完整进程树和临时目录由共享执行边界拥有；适配器负责原生
协议和用量，不重新推断同一份所有权。Windows 复用精确 Job，
POSIX 必须保障 core 突然死亡后的整组退出，不能只依赖正常 finally
或适配器仍存活时的轮询。安装前独立调用、后台服务与摘要保持各自寿命。
当前实现仍有误判和漏清理，具体发现、收敛决定及验证范围见
[执行生命周期与更新事务收敛](execution-lifecycle-convergence.md)。

## 权威状态、恢复与回收

Markdown 是当前正文权威。SQLite 保存必要游标、队列、授权/身份关联与外部操作结果；ReMe 是可重建派生索引。缺损的权威库不能按首次使用建立空库，不能再拿空 snapshot 删除正文、尝试历史或 unknown 回执。初始化要先区分真正新状态与已有状态，校验必要表/字段/版本；创建意图中断也不能自动变成第二次首次使用。

所有权标记只说明初始化和版本归属，不复制业务数据，也不负责重建主账本。损坏阻止变更并保留资料，准确错误交给调用者。只有已知有效权威才可驱动派生索引重建或垃圾回收。事务中先完整验证候选再切换语料快照，坏末尾不得留下已宣称成功的半个语料库。

只保留当前有效正文和必要未决发送材料，不维护正文历史副本。收到精确提交回执后按当前发布/同步合同回收 frozen payload；新观察仍可追加，不能清掉未提交部分。当前远端 head/main 的独立修改必须核对；被拒绝、撤下或冲突的内容不自动复活。历史引用保持其字面身份，不把当前内容冒充旧版本。

## 安装、重载与服务归属

2026-10-15 复用审查将插件分发/选择交回原生 Git marketplace，依赖安装
交给锁定的标准包工具。两端正在删除旧 updater、专用调度及重复选择状态，
共享平台实现已经进入重构，最终 native 验收尚未完成；
具体删除范围和宿主缓存差异见[复用审查](native-runtime-reuse.md)。
未发布实现不保留多代兼容、版本排序、后继链或自动迁移框架。
正式 `0.0.1` 固定版本与源码，
不跟踪开发 main；已发生的 unknown 操作仍保留原回执并只读核对。

适配器提交、唯一 runtime pins 与 product contract 共同指定一套产品组合；内容仓声明 schema、validator 和 Bot 规则。候选在自己的解释器中验证自身接口与实际安装包，启动入口不 import 另一版本的私有 API。普通内容更新沿用同一合同；合同变化需要匹配的组合。

运行时可执行代码提交、公开材料与审核格式、可信审核器代码提交是独立身份。产品选择公开仓精确声明及其摘要；runtime parser 必须接受声明的格式与审核语义，可信公开基准绑定实际审核代码。运行时修复不要求审核器同步换版，但必须核对真实安装 pin、声明摘要和互操作行为；候选内容不能选择客户端执行代码。既有候选回执同时绑定产品、源码和 runtime pins，不能用版本身份分离跳过交付校验。

各仓库正式发布前可以直接重写中间实现，无须为其保留代码兼容分支。
现存正文、游标、授权、费用和 unknown 是用户事实，仍须保留；不能借重写
代码删除它们或自动重放。正式发布后根据实际字段、存储格式和接口合同变化
设计必要兼容，不用产品版本号代替数据格式判断。

插件入口直接绑定该发布的 runtime identity；运行环境位于宿主缓存之外，
依赖与适配器非 editable 安装。uv 负责依赖锁和环境同步，完成发布仅在
包校验通过后进行，已发布环境不再原地同步或修补。尚可能被宿主旧定义、
活动服务或未决操作引用的环境不自动回收；本轮不新增运行时租约管理器。
不再维护独立于宿主的全局产品 current 指针。宿主可能仍引用的 Hook
路径须验证，不能凭 TTL 猜测；入口失效须报告，不能悄悄重分派到旧副本。

首次空 profile 可以准备并保存一套安装绑定。同一绑定直接复用；已有不同
绑定时拒绝覆盖配置或退休服务。普通 SessionStart、MCP 和迟到 Hook 都不是
跨版本切换授权。未发布开发安装可以另建独立 profile，原数据和失败回执
保留；本轮不实现旧安装透明转换。

常驻 MCP 在进程内固定安装身份，每次操作产生副作用前在已有 profile 锁内
复核；变化时报告需要重新加载。动态授权仍独立读取。短 Stop 只使用其精确
安装，不触发安装或转发到别的运行时，先保存准入再唤醒对应服务。
控制面探测期限不传递为模型总时限。

知识组件提供精确服务停用/恢复边界，使用完整配置 fingerprint、认证连接、
启动锁和消费锁；退休记录阻止迟到 wake 重启已停服务，不携带后继路由。
实际业务忙和状态 unknown 均不授权清理。不可变 engine 配置不原地重写。
没有 endpoint 也不证明不存在启动中的服务，后续清理错误不能抹去已停止事实。

插件按宿主支持的时机加载；未来正式升级若需要重载，应明确告知。当前不承诺
宿主关闭时后台追新、跨版本即时热切换或旧 MCP 透明连接新服务。

恢复使用选定 Harness profile 和已有模型来源，不能用进程 ready 冒充模型可用。安装文件、宿主已加载定义、Hook 信任是不同事实；遵循宿主原生信任机制。插件下载和更新触发采用宿主机制，不另建轮询与退避调度器。MindIE 的兼容或运行环境准备失败须可见，不能报告成更新成功。未知写入不自动重放；已知配置/内容/兼容错误立即可见。

原生安装目标的回读与原写入者已结束是独立事实；尚未确认写入树结束时，
一次匹配快照不能授权再次安装。已经确认退出后的次级清理/记录错误
不能抹去安装结果。旧开发操作的未决回执留作事实，可独立只读调查；
不为处理这些历史证据继续分发旧 updater 或 check/recover 状态机。

## 验收边界

按最终组合验证首轮自动关联、fork/兄弟任务隔离、撤权、长静默、所有者退出、断连、已知结果后记录失败、缺库保留正文、未决副作用恢复和升级后原 job 可控。核对真实调用者收到的结果及副作用，不以内部 flag、进程存活或测试数代替。

组件测试、原生安装/Stop/MCP、实际 SSH/NPU、公开 PR/Bot 和新任务复用分别记录提交与证据。本轮开发样本、测试等待时间或模型预算不是产品门槛。历史结果可按其版本和适用范围复用，不要求每次重复全量验收，也不将旧证据写为当前版本已通过。
