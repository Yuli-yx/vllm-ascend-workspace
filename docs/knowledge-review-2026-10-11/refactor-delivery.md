## 已实现的职责与恢复边界

编排重构为[知识 PR #63](https://github.com/mindie-agent/knowledge/pull/63)的 `484a5b5aa98ce93cf5cf9b3b550fab45b420fc4b`，基于已合入的故障修复 PR #62。该轮合入 `5d13cdc48d44f8e6ff14cd5a3fccc6640357a024`，树与候选完全相同，并保留候选为祖先。随后完成同一交接边界的 PR #64，最终精确身份见下文。没有变更正文格式、数据库 schema 或共享依赖。

| 责任 | 业务事实与恢复来源 |
| --- | --- |
| `OperationOwner` | 每个捕获、索引、组包和投稿拥有独立身份、授权版本及不可复用的取消标记；旧授权撤销不会取消已接收的新授权工作。准入和更新冻结共用锁，关闭服务取消全部实际操作；读取与只读对账各自独立 |
| `Engine` | 调度并复核原生身份与授权，不再通过全局取消标记推断另一 worker 的进度 |
| `IndexQueue` / `SummaryLedger` | 使用同一 Store 事务管理增量进度与既有模型尝试事实。应用已返回索引、完成尝试和计算整包就绪一起提交；返回结果可本地恢复，失败或未知付费输入不自动重放 |
| `PublicationWorker` | 复用原冻结包与发布身份，负责投稿、只读对账和回执。已确认结果分别报告本地记账、清理失败；未知写入只核对原操作 |
| 原有服务退休边界 | 原配置标记、启动锁、准入锁与 lifetime consumer lock 共同排除旧 wake 和并发所有者；完整退休还要回收已确认失效的连接发现文件，避免下一 owner 初始化期间读到上一配置的连接 |
| 现有 `Store` / `MaterialStore` | 完整脱敏正文和游标仍一起提交；未发送批次和未组包反馈的撤销改为同一事务。公共成员切换和 ReMe 派生索引继续复用现有边界，没有第二套状态权威 |

旧增量索引失败后，后续增量仍能保存并整理；整包仍明确未就绪。显式重试旧失败增量复用后续已完成结果，已有调用账保持不变。回归测试核对真实进程、SQLite 事务、正文、调用次数和实际结果，不把等待时长当作产品门槛。

运行时提交无需等于可信校验器提交。当前公开格式、声明摘要、Bot pin 和产品/回执 schema 保持原样；跨版本组件测试使用正常独立安装的可信校验器，校验新版实际产出的包，并拒绝篡改正文、错误声明摘要、不支持的格式和错误实际校验器 pin。格式或审核合同变化仍需要明确兼容的产品组合。

全量验收同时修正了两处原有错误交付：配置成功后绑定读取失败会被缺失 `status` 引发的 KeyError 遮蔽；准入错误会被独立进程清理失败遮蔽。现在保留配置已完成与原准入错误，另报清理失败；成功响应遇到清理失败也不报告完整成功。
